# AWS 변경 전 상태 스냅샷 (2026-07-25)

계정 `185353921021` / 리전 `ap-northeast-1` / 함수 `link-sphere-api`

## 변경 전 상태

| 항목 | 변경 전 값 |
| ---- | ---------- |
| `$LATEST` MemorySize | **1024** |
| `$LATEST` Timeout | 120 |
| Runtime / Arch | java17 / arm64 |
| SnapStart ApplyOn | PublishedVersions |
| `prod` alias → 버전 | **39** |
| 버전 39 MemorySize | 1024 |
| 버전 39 SnapStart | On |
| S3 lifecycle | **없음** (NoSuchLifecycleConfiguration) |
| S3 버전 관리 | 비활성 (Status 없음) |
| EventBridge 룰 | **없음** (ListRules 빈 배열) |
| AWS CLI 기본 리전 | `northeast-1` (오타 — `ap-` 누락, `aws configure set region ap-northeast-1`로 수정함) |

## 롤백 커맨드

```bash
R=ap-northeast-1; F=link-sphere-api

# 1. 메모리 되돌리기
aws lambda update-function-configuration \
  --function-name $F --memory-size 1024 --region $R

# 2. prod alias를 기존 버전 39로 되돌리기 (문제 있는 새 버전 발행 시)
aws lambda update-alias \
  --function-name $F --name prod --function-version 39 --region $R

# 3. S3 lifecycle 제거
aws s3api delete-bucket-lifecycle --bucket link-sphere-lambda-deploy

# 4. EventBridge 워밍핑 제거
#    주의: 인라인 정책 warmup-rule-setup을 회수했다면 먼저 다시 붙여야 실행된다
aws events remove-targets --rule link-sphere-api-warmup --ids warmup --region $R
aws events delete-rule --name link-sphere-api-warmup --region $R
aws lambda remove-permission --function-name $F --qualifier prod \
  --statement-id EventBridgeWarmup --region $R
```

## 주의

- 버전 39는 **메모리 1024로 구워진 스냅샷**이다. 메모리를 2048로 올려도 기존 버전 39는
  1024인 채로 남으므로, alias를 39로 되돌리면 메모리도 함께 되돌아간다 (안전한 롤백 경로).
- 메모리 2048은 다음 배포에서 `publish-version` 할 때 새 스냅샷에 반영된다.
- S3 버전 관리가 비활성이므로 단순 `Expiration`만으로 실제 삭제가 일어난다
  (`NoncurrentVersionExpiration` 불필요).
